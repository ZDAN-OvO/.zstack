# 阶梯记录：把本季度数字填进上季度季报模板

- 任务起点：把本季度 BI 导出的 CSV 数字填进上季度季报模板
- 用途：周一管理层会，决定下季度预算分配
- 现状：已定顶层 Rung 3（用户改写版），停在此层，交出
- 记录时间：2026-11-08

## 阶梯

| 层 | 任务 | 状态 |
| --- | --- | --- |
| Rung 0 | 填模板 | 基线（保底做法） |
| Rung 1 | 解释变化、原因、下一步 | 已接受 |
| Rung 2 | 挑出最急的三个预算决策，各写支持与反对 | 已接受 |
| **Rung 3（顶层，交出）** | 用两个季度的数据做出监测规则草案，标明回测不足 | 已接受（用户改写后定稿） |

## Rung 3 定稿定义

目标：让季报从"每月/每季手工填一次"变成"持续监测、只在显著变化时提醒"，本次只交规则草案，不交落地上线。

范围：
1. 用现有 2 个季度（本季度 + 上季度）的 CSV 做出监测规则草案：
   - 监测哪些指标（与季报模板字段对齐）
   - 每个指标的"显著变化"判定口径（阈值、同比/环比、绝对量 vs 百分比）
   - 提醒的触发条件、频率上限、去重方式
   - 提醒内容应包含什么（指标、变化幅度、可能原因候选）
2. 明确标注回测不足：只有 2 个季度、2 个数据点，无法验证阈值的误报/漏报率；每条规则旁注明"依据的样本量与置信程度"。

不做（本层边界）：
- 不搭自动监测、不接提醒渠道、不做历史回测验证
- 不评估"季报是否该存在"这类组织问题
- 不改季报模板本身

依赖输入：
- 本季度 CSV、上季度 CSV（已有）
- 提醒渠道（邮件 / IM 群 / 其他）——交给执行方确认，未定不影响草案，但需在草案里留出可替换的渠道位

回退：若草案在 2 个季度数据下无法给出可信阈值，退一层，按 Rung 1 + Rung 2 交付（解释变化 + 三个预算决策的支持与反对）。
