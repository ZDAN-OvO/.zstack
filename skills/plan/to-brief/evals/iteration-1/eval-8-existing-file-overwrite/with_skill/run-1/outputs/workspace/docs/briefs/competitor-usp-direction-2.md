# Brief: 下季度产品方向定调——押「更好用」还是「更便宜」，给出一个明确建议与理由

- Stage: decide
- Source: 用户原话：给下季度产品方向决策（更好用 vs 更便宜）提供依据，最后要一个明确建议和理由；背景是年营收约 200 万美元的营销自动化 SaaS，客户为 50 人以下公司，常嫌复杂和贵，去年调价反响不好；素材用三家竞品官网和用户自己整理的评论，不用二手评论文章，查不到就留白；不要编 ARR/用户数，不动付费等级架构；先给 outline，审过再展开。

## Goal
- 支撑一个决定：下季度产品与定位的投入押「更好用」还是「更便宜」；输出必须收敛到一个明确建议，不能以「两者都要」或并列选项收尾。
- 建议须给出取舍理由：为什么选这一边、放弃另一边的代价是什么、在什么条件下这个判断会翻转。
- 依据来自三处对照：竞品在易用性与价格上的实际做法、用户评论中抱怨的分布、我方营收体量与去年调价的历史结果。

## Context
- 公司：营销自动化 SaaS，年营收约 200 万美元；客户以 50 人以下公司为主。
- 已知痛点：客户常说产品复杂、价格贵；去年调价的市场反响不好，这构成对「再调价/直接降价」路径的历史否决信号。
- 决策者即用户本人，结论用于下季度方向定调；文档要能被非本团队的人读懂并据此开会。
- 我方现有付费层级结构是既定事实，只作为观察对象和竞品价位对照的基准，不是可改动的变量。

## Materials
- 一手优先：三家竞品的官网，重点是定价页、产品/功能页、上手流程或模板库页；名单未点名，取值见 Assumptions。
- 一手优先：用户自己整理的用户评论材料（用户提供；本工作区内暂无该文件，执行前需用户给出路径或原文）。
- 二手评论聚合文章、榜单、SEO 评测站一律不用；也不引用转述这些内容的第三方数据。
- 缺数据处理：查不到的字段（具体价格、免费层、用户规模）留空并标注「未查到」，不估算、不补全。

## Boundaries
- 不编造 ARR、用户数、增长率、市占率、转化率等任何指标；无来源即写「未知」。
- 不建议改动付费等级架构（层数、每层包含什么、是否合并拆分）；定价定位、包装与表达可以提建议。
- 不写只有形容词没有取舍的比较（如「A 更友好、B 略贵」）；每条差异须点明它对谁意味着什么代价。
- 不把「降价」或「加功能」当默认答案，两个方向都必须先过用户证据再下结论。
- 不引入 Materials 之外的来源，包括任何二手评论文章。

## Done
- 第一步交付一份 Markdown outline：3–5 条关键差异、一句推荐方向、支撑理由骨架，写到 outline 即停，等用户审阅。
- outline 通过后才展开完整报告；报告同样是 Markdown，含结论、证据、风险与判断翻转条件。
- 两个审阅关口各确认一次：outline 一次、最终建议一次；未获确认不往下写。

## Assumptions
- 三家竞品未点名：默认取用户评论里出现最多、且规模与我方相近的三家；用户可直接替换名单。
- 用户评论材料不在工作区：执行时先索取文件或原文；若拿不到，只凭竞品官网出 outline，并在文中标注证据缺口，不自行补评论。
- 「更好用」按降低上手与日常操作成本理解（onboarding、模板、搭建自动化所需步骤）；「更便宜」按总拥有成本与价格感知理解，不只看标价。
- 去年调价的具体幅度与反响细节未提供：按「反响不好」这一定性处理，不虚构数字。
