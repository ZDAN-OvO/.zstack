# Brief：下季度产品方向 —— 更好用 vs 更便宜

- 阶段：**Stage 1（只出 outline，等审）**
- 状态：素材未到齐，存在阻塞项（见「需要用户提供」）
- 本文件为新 brief；同目录 `competitor-usp-direction.md` 属其他任务，标注了不要覆盖，**不得改动**

## 1. 要做的决策

下季度产品投入优先投哪一边：

- **A. 更好用**：降低复杂度、缩短上手时间、减少配置/学习成本
- **B. 更便宜**：降价格门槛、提高价格感知的价值、改善"贵"的体感

产出必须落在一个**明确建议**上（选 A、选 B，或明确"先 A 后 B"并给出顺序理由），并说明为什么另一个不选。不允许用"两者都重要"收尾。

允许的第三种答案：证据显示两者不该放在同一预算池竞争（例如"贵"其实是价值没被感知，属沟通问题而非定价问题）。但即使这样，也必须回答"下季度资源优先投哪里"。

## 2. 背景（用户已给，不得扩写）

- 营销自动化 SaaS，年营收约 200 万美元
- 客户是 50 人以下公司
- 客户常见抱怨：太复杂、太贵
- 去年调过价，市场反响不好

以上是**全部**已给事实。任何其他数字（用户数、客户数、churn、转化率、竞品价格、市场份额、增速）都视为未知。

## 3. 硬约束

1. **不编造数字。** ARR、用户数、客户数、增长率、竞品定价/份额一律不得推测、不得用"行业通常"填补。唯一可用数字是"约 200 万美元年营收"，且需标注为用户提供。
2. **不动付费等级架构。** 不重新划分 tier、不改功能与层级的绑定关系、不设计新套餐结构。可以讨论价格水平、价值表达、试用/降级路径。若分析指向"必须改层级"，只能作为超出范围的待决项列出，不得给方案。
3. **素材封闭。** 只用两类来源：三家竞品官网、用户自己整理的用户评论。**禁止**二手评论文章、评测博客、聚合站、媒体转述、G2/Capterra 类平台的转述内容、以及模型记忆中的"众所周知"结论。
4. **查不到就留白。** 缺失处写 `[未找到：<查了什么、查了哪些页面/日期>]`，不要用推测、类比或常识补位。留白比编造优先。
5. **区分证据类型。** 官网内容 = 厂商自述（是"他们这么说"，不是事实）；用户评论 = 自报样本（不可外推为整体客户比例）。分析者归纳必须与原话分开标注。

## 4. 素材与取证规则

| 素材 | 取什么 | 必须记录 |
|---|---|---|
| 三家竞品官网 | 定价页、功能/能力页、目标客群页、上手/文档/模板页 | URL、抓取日期、原文摘录（≤2 句/处） |
| 用户评论 | 用户提供的原始评论集 | 来源形态（文件/表格/截图）、条数、时间跨度 |

- 竞品对照只做**定位层**（他们把自己卖给谁、主打什么、怎么表达价格），不做逐功能打分大表。
- 用户评论按主题聚类（复杂/学习成本、价格、价值不清、切换成本、缺功能），并标注每个主题的条数与原话样例；**不给百分比**，除非分母明确且样本可代表。
- 每条结论后面挂来源；无来源的判断写成"推断"或"假设"。

## 5. 需要用户提供（阻塞项，缺一项就不能进入 Stage 2）

1. **三家竞品的名称与官网 URL**（不自行挑选替代品；未给就留白，不要猜）
2. **用户评论素材的位置与形式**（导出文件路径 / 链接 / 表格 / 截图）
3. **判定口径**：内部是否已有可用的信号（激活率、support 工单主题、churn/降级原因、赢单丢单原因）？有则给，没有就明说"无"
4. **产能约束**：下季度可投入的工程/设计量级（人周或相对比例），用于比较两个方向的代价
5. **去年调价的复盘材料**：调的是什么（价格水平/包装/折扣）、时间点、"反响不好"的具体表现（投诉、流失、降级、销售阻力）
6. **决策场景**：谁拍板、什么会议、要多长（决定 memo 的篇幅与详略）

## 6. 交付物与阶段门

### Stage 1（本次交付）

只给 **outline**：8–12 节，每节一句话说明"这节回答什么问题、需要什么证据"。
**不含结论、不含建议、不含任何研究发现。** 交付后停下等审。

### Stage 2（审过之后）

展开成决策 memo，必须包含：

- 结论先行：建议 + 3–5 条理由（每条挂证据）
- 明确写出"为什么不选另一个方向"
- 置信度：证据够就写高/中，不够就写低 + 还缺什么
- 反证条件：出现什么信号会推翻这个建议
- 季度内可执行动作（不涉及改层级）
- 留白清单与未解问题

## 7. 建议的 memo 结构（骨架，待审后可改）

1. 结论与建议（Stage 2 才填）
2. 决策问题、选项定义、判定标准
3. 已知事实边界（哪些是用户给的，哪些未知）
4. 客户痛点证据：**复杂度** 与 **价格** 分开列，不合并且不互相解释
5. 竞品定位对照（三家官网自述，标注为厂商声称）
6. 用户评论证据（主题 + 原话 + 样本局限）
7. "贵"的拆解：绝对价格高 / 价值没被感知 / 切换与学习成本高 —— 三者证据分别是什么
8. 去年调价复盘（素材缺失则留白）
9. 两个方向的代价、可逆性、对定位与信任的影响
10. 建议与理由（含不选另一边的理由）
11. 反证条件与最小验证动作
12. 留白与未解问题

## 10. 给执行者的提醒

- 这个决策的证据基础很薄（三家官网 + 一批自选评论，没有留存/流失数据）。**证据不足时给低置信度建议并说清缺什么，比给一个漂亮但无支撑的结论更有价值。**
- 不要把"客户说贵"直接等同于"应该降价"：先分清是价格问题还是价值感知问题，这是本 brief 最容易被做错的地方。
- 不要把"客户说复杂"直接等同于"要砍功能"：复杂度可能来自配置路径、术语、上手引导，而非功能数量。
