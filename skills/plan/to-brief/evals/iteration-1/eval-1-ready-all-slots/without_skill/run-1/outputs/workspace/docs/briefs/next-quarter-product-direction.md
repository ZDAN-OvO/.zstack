# Brief：下季度产品方向 —— 更好用 vs 更便宜

| 字段 | 内容 |
| --- | --- |
| 状态 | 待用户审 outline（本文件只定义任务与规则，不含任何结论） |
| 决策问题 | 下季度把有限的产品/定价投入放在「降低使用复杂度」还是「降低价格门槛」 |
| 交付物 | 决策备忘：先 outline → 用户审 → 再展开全文 |
| 读者 | 产品方向决策人（用户本人） |
| 素材状态 | 三家竞品名单未定、用户评论集未提供、去年调价细节未提供（见 §9） |

## 1. 背景（用户给定，不要二次加工）

- 营销自动化 SaaS，年营收约 200 万美元（**用户口径，未核实**）。
- 客户为 50 人以下公司。
- 客户反复反馈：产品太复杂、太贵。
- 去年调过一次价，市场反响不好（具体改动与反响证据待补）。

以上是唯一可直接引用的业务事实。除此之外不得补充背景故事、市场规模或客户画像细节。

## 2. 要回答的问题

**主问题**：下季度应把主要投入放在「更好用」（降低学习成本与操作复杂度）还是「更便宜」（降低价格门槛与价格感知）？

**必须交付**：
1. 一个明确的建议（选哪条为主，或明确的主次与顺序），不是「两者都重要、需要平衡」。
2. 支撑建议的理由，每条理由挂到具体证据编号。
3. 反证条件：什么证据出现时这个建议应当被推翻。
4. 下季度可验证的最小动作（90 天内能看出方向对错的那种），不排期、不写方案。

若论证后发现这是伪二分（例如「感知复杂」本身就是价格感知的一部分），可以指出并重构选项，但仍须给出一个首选方向，并说明重构依据。

## 3. 素材与取数规则

| 素材 | 来源 | 当前状态 | 使用规则 |
| --- | --- | --- | --- |
| 竞品官网 | 三家竞品官网原文：首页定位、定价页、功能/方案页、公开帮助文档 | 名单待用户指定 | 一手来源，可引用原文与公开价格，须记 URL + 采集日期 |
| 用户评论 | 用户自己整理的评论集 | 未提供 | 一手来源，按评论编号引用原话，须记来源渠道与时间范围 |
| 其他 | — | 不使用 | 见下方禁止项 |

**禁止项**：
- 不引用二手评论文章、测评汇总、行业报告、第三方评论平台（G2 / Capterra / Reddit 帖等）页面内容作为证据。这类内容只能用来找线索，不能入文。
- 不自行挑选或替换竞品：竞品名单由用户指定，自行选三家会让对照基准失真。
- 不用模型记忆或行业常识补齐任何事实。

**证据登记格式**（全文统一编号 E01、E02…）：

> `E07` ｜ 主张：竞品 B 的入门价明显低于同档 ｜ 原文摘录（≤50 字）｜ 来源：URL 或评论编号 ｜ 采集日期 ｜ 偏差说明（官网是营销话术 / 评论是自选样本）

**留白规则**：查不到就写「未查到」，并列出检索词与检索日期。所有留白集中到文末「空白清单」一节，不允许在正文里用推测句填坑（「大概」「通常」「据了解」一律不许出现在证据位）。

## 4. 数字纪律

- 唯一允许出现的规模数字：年营收约 200 万美元，且必须标注为用户口径、未核实。
- 禁止出现任何未提供或未核实的量化值，包括但不限于：客户数、用户数、ARR 增速、流失率、转化率、客单价、NPS、竞品收入或客户量、市场规模。
- 竞品公开标价属于官网事实，可引用，须带页面日期；不得由其价格反推其营收、客户量或毛利。
- 需要量化才能比较时，改用**敏感性框架**：写成公式 + 变量表（例：`降价 d% 后维持毛利所需的客户增长 = d / (m − d)`，`m` 为毛利率），变量留空或标「假设，待用户确认」，不填具体数值。

## 5. 硬约束

1. **付费等级架构不动**：层级数量、层级命名、各层功能归属与 gate 不重排、不新增或合并层级。任何必须动架构才能成立的「更便宜」路径，标注「超出本 brief 范围，需另行决策」，不得自行设计替代架构。
2. 「更便宜」只在不动架构的杠杆内讨论，逐条列出并标注证据需求：标价水平、年付/预付折扣、试用与退款政策、席位或用量计费参数、增值服务与 onboarding、成本侧让利（不涉及功能重分配的部分）。
3. 不写定价页文案、不做视觉或交互方案、不排期、不估工时。
4. 不做竞品功能大表（逐项打勾式对标），只提取与「复杂」「贵」两条假设直接相关的差异。

## 6. 展开时的分析骨架

1. **决策标准先行**：明确用什么判据选方向（例如：哪个方向更能解释现有客户的「复杂/贵」抱怨，哪个方向在不改架构下更可执行），并写清判据权重来源。
2. **症状证据**：「复杂」和「贵」各自的具体表现 —— 从评论集中编码得出，区分「学不会」「用不到那么多功能」「单价超预算」「不值这个价」四类不同病因。
3. **竞品定位与价格带**：三家官网各自的目标客群、价值主张、定价页结构（是否公开价、是否有免费/试用、入门门槛），只取公开原文。
4. **评论编码**：按主题归类并计数，保留代表性原话；说明样本偏差（谁在评论、时间范围、是否只覆盖不满客户）。
5. **两条路线的因果链与关键假设**：更好用 → 上手快/少支持/口碑/留存；更便宜 → 转化/降流失/毛利。每条链标注「哪一环是假设、需要什么证据」。
6. **检验伪二分**：两条路线是否共享同一根因；若共享，投入顺序应如何调整。
7. **财务与风险边界**：用 §4 的敏感性框架说明两条路线的盈亏条件，标注缺失变量；列出误判风险（见 §10）。
8. **建议**：首选方向 + 理由（挂证据编号）+ 反证条件 + 90 天可验证动作。

## 7. Outline 门槛（第一个交付物）

只交 outline，**不写正文论证**。outline 需包含：

- 每节一句话：这节回答什么、依赖哪类证据、证据缺失时如何留白。
- 已知证据缺口清单（至少含：竞品名单、评论集、调价细节、毛利与流失数据）。
- 判定矩阵雏形：列出「选更好用」与「选更便宜」各自的判别条件（只有条件，没有结论）。
- 图表清单 ≤4 张，每张注明数据来源；无来源的图不许进 outline。
- 需要用户裁决的问题列表（与 §9 一致）。
- 全文篇幅预估。

用户批准 outline 后才展开；展开时不得新增 outline 之外的大节，新增需先说明理由。

## 8. 验收标准

- [ ] 结论唯一且明确，能一句话说清「下季度押哪边、为什么」。
- [ ] 每条关键主张都能回溯到证据编号；无编号的主张不得进入结论段。
- [ ] 有反证条件，且是可用数据检验的条件，不是「如果情况变化」这类空话。
- [ ] 全文数字逐个可溯源：除 200 万美元营收外，没有任何未经确认的量化值。
- [ ] 空白清单完整，且正文对应位置确实留白而非填推测。
- [ ] 明确声明未改动付费等级架构；越界项已标注「需另行决策」。
- [ ] 未使用任何二手评论文章或第三方评论平台内容作为证据。
- [ ] 未出现定价页文案、视觉方案、排期。

## 9. 已知缺口（需用户确认后才能展开）

1. 三家竞品分别是谁（名称或官网域名）。
2. 用户整理的评论集在哪里、多少条、覆盖什么时间范围、来自哪些渠道。
3. 去年调价改了什么（价格水平 / 层级结构 / 计费方式），「反响不好」的具体表现是什么（流失、投诉、退款、销售阻力）。
4. 是否可获得毛利率、流失率、试用转化等内部数据；若无，敏感性框架全部走假设表。
5. 「更便宜」是否只允许调标价，还是也允许调折扣/试用/计费参数（后者仍在架构内，但影响面不同）。
6. 决策截止时间与决策人，是否需要给他人汇报（决定文档详略）。

## 10. 风险（写作时需主动处理）

- **伪二分**：把「复杂」和「贵」当两个独立病因，可能掩盖真正根因（例如功能过剩既造成复杂也造成价格不可接受）。
- **自选样本偏差**：用户整理的评论多半来自不满客户或特定渠道，不能当作整体客户分布；须在文中明说。
- **官网话术当事实**：竞品官网的「简单」「几分钟上手」是营销主张，只能作为其定位证据，不能作为其产品实际易用性的证据。
- **调价创伤归因**：去年调价失败会让所有负面反馈都看起来像价格问题，需专门检验「复杂」类抱怨是否在调价前就存在。
- **用降价掩盖成本结构**：若毛利与支持成本未知，任何降价建议都只能停留在条件式表述，不得给出「降价 X% 即可」的结论。
