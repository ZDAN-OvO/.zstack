# Brief: 下季度产品方向 —— USP 押「更好用」还是「更便宜」，并收在一个明确建议上

- Stage: decide
- Source: 帮我写个 brief：目标是给下季度产品方向决策（更好用 vs 更便宜）提供依据，最后要一个明确建议和理由。背景：年营收约 200 万美元的营销自动化 SaaS，客户是 50 人以下公司，常嫌复杂和贵，去年调价反响不好。素材用三家竞品官网和我整理的用户评论，不用二手评论文章，查不到就留白。不要编 ARR/用户数，不动付费等级架构。先给 outline，审过再展开。

## Goal
- 支撑下季度产品方向的一次二选一决策：产品叙事与投入押「更好用」还是「更便宜」。
- 结尾必须给一个明确建议（二选一，不是两者都做），并给出理由。
- 理由要能对上现实约束：50 人以下客群、对复杂度和价格的抱怨、去年调价的反响。

## Context
- 公司：营销自动化 SaaS，年营收约 200 万美元；客群是 50 人以下的公司。
- 已知痛点：客户常抱怨产品复杂、价格贵。
- 去年调价反响不好：涨价这条路已经被烧过一次，任何涉及价格动作的建议都要正面处理这段历史。
- 对标范围应与自身同量级、同客群，不拿企业级营销云做基准。

## Materials
- 主源 A：三家竞品官网（产品页、定价页、上手与文档页）。优先级：定价页与上手流程 > 功能清单 > 博客与营销页。
- 主源 B：你整理的用户评论（一手摘录），作为客户抱怨与取舍选择的证据。
- 禁用：二手评论文章、测评聚合站、榜单与软文；它们不进证据链，也不进引用。
- 价格、套餐限制、客户数等查不到的项：留空并标 not found，不推测、不用行业均值代填。

## Boundaries
- 不编造 ARR、用户数、增长率、留存等任何量化指标；没有来源就写「未知」。
- 不动付费等级架构（档位数量、各档包含什么、限额）；价格定位与档内包装可以讨论。
- 不写只有形容词、没有权衡的比较；每条判断要指名代价。
- 不把「两个方向都做」当建议，也不把去年调价失败简单归因为「价格不够低」。

## Done
- 先只交 outline（Markdown，一页内）：3 个关键差异、推荐方向、理由，每条理由标出对应的证据来源。
- outline 经我确认后才展开全文；未确认不写全文。
- 全文形态：一页内可直接转发的决策稿，结论在最前；缺失证据在文中标 not found，而不是绕开。

## Assumptions
- 三家竞品的具体名单你未点名：按覆盖「便宜但功能浅」与「功能深但复杂」两端，取 Mailchimp、ActiveCampaign、Brevo；可随时替换。
- 「不动付费等级架构」按「档位结构固定、价格定位与档内包装可讨论」理解；否则「更便宜」这个方向无法进入讨论。
- 你的用户评论材料还没出现在工作区（docs/briefs 下只有旧 brief）：按待提供处理，材料到位前相关结论留空。
- 篇幅与体裁按默认：outline 一页内；全文一页内可转发。
