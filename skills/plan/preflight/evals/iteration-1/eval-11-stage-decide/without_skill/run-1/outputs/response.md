**Postgres。** 两条标准都直接指向它：

1. **团队只会 SQL**：Postgres 就是 SQL，学习成本几乎为零；MongoDB 的查询语言、聚合管道、schema 设计思路都得重新学，团队会在最不该踩坑的阶段踩坑。
2. **数据强关系**：强关系意味着外键、JOIN、事务一致性。这是 Postgres 的主场；MongoDB 要靠应用层手工维护引用、`$lookup` 模拟 JOIN、多文档事务（能用但更笨重），本质是在跟数据库的设计取向对抗。

补充两点：

- 怕 JSON 灵活字段不是选 Mongo 的理由 —— Postgres 的 `jsonb` 能存半结构化数据，还支持索引和查询，等于"关系为主 + 局部灵活"两全。
- 什么情况下我会改口选 Mongo：文档天然自包含、几乎不做跨集合关联、需要横向分片写入海量日志/事件类数据。你的两条标准都不属于这种情况。

结论：**用 Postgres，别再评估了。**
