# Brief: 下季度产品方向（更好用 vs 更便宜）的竞品与用户证据，收在一个明确建议上

- Stage: execute
- Source: 用户原话（节选）："目标是给下季度产品方向决策（更好用 vs 更便宜）提供依据，最后要一个明确建议和理由……素材用三家竞品官网和我整理的用户评论，不用二手评论文章，查不到就留白……先给 outline，审过再展开。"

## Goal

- 服务下季度产品方向决策：主打「更好用」还是「更便宜」，二选一，不下注第三条路。
- 输出以一条明确建议收尾，理由必须落在竞品定位与你整理的用户评论上，并说明为什么选这一边、放弃另一边的代价是什么。
- 结论要能直接支撑拍板，读完不需要再补一轮调研。

## Context

- 公司是营销自动化 SaaS，年营收约 200 万美元（按你给的口径使用，不再细化或反推）。
- 客户是 50 人以下的公司；他们常反馈产品复杂、价格贵，两条抱怨同时存在，本任务就是判断哪条更该被定位接住。
- 去年调价反响不好：涨价已有负面先例，「更便宜」这一边的评估要把它当约束，而不是当空白。
- 本次判的是定位取舍（卖点押易用还是押价格），不是具体价目表或折扣方案。

## Materials

- 一手素材，按优先级：三家竞品官网（定价页、功能/产品页、面向小团队的说明页）为第一优先；你整理的用户评论为第二优先，用于判断痛点是复杂度还是价格。
- 只用竞品官方站点与你整理的用户评论；不要引用二手评论文章、评测汇总站、SEO 内容农场。
- 竞品官网上查不到的字段（价格档位、是否包含某项能力）留空并标「未找到」，不估算、不按同类产品推测。
- 你整理的评论若没覆盖某个问题（如某类客户的价格敏感度），写「未找到」留白，不用常识补。
- 引用要可追溯：竞品结论注明来自哪个站点的哪个页面；用户结论可复述评论原话片段，不改写强度、不合并不同客户的说法。

## Boundaries

- 不编造 ARR、用户数、增长率、市场份额等任何素材里没有的数字；缺就写「未找到」。
- 不改动、也不建议改动付费等级架构（档位数量、各档包含什么、升降级规则）；定价的对外表达与定位可以讨论。
- 不做只带形容词的比较（如「A 更强大、B 更友好」）；每条差异必须写出取舍：谁在哪类客户/场景占优，代价是什么。
- 不把「更好用」和「更便宜」同时推荐；必须选一边，另一边作为代价明确写出。
- 不引入三家竞品与你评论之外的新素材，也不做市场规模、赛道趋势、竞品内部经营状况的判断。

## Done

- 第一步只交 outline：3 条关键竞品差异（每条带取舍）、用户评论反映的主痛点（复杂度 vs 价格，给出出现频次或计数）、建议方向与理由骨架；不含正文展开。
- outline 经你确认或修改后才写完整报告；报告按已确认的结构展开，不新增未审过的方向。
- 完整报告是 Markdown，结论前置（第一段即建议与理由），一页到两页读完，每条结论可回溯到 Materials 中的来源。
- 若素材不足以支撑某一边，outline 直接写「证据不足」并给出补素材的最小清单，不硬凑结论。

## Assumptions

- 三家竞品未点名：执行方按「同段位、同样面向 50 人以下公司的营销自动化产品」自行选三家，在 outline 首段列出名单，你可直接替换（错了只损失一个 outline）。
