README 这一轮先不写。原因：README 不是一种文体，是一个动作——同一份文件，给招聘方扫和给接手的人跑，内容几乎不重叠，现在动笔只会写出一个谁都能套的模板。先定两件事。

❓ **Q1** - **谁会打开它，在什么时刻**：三种典型时刻，选一个（也可以说第四种）：

- a. 外部评估者——招聘方或同行顺着你的项目列表点进来，还不知道这项目是什么，正在决定要不要多花五分钟；
- b. 已经决定用它的人——新协作者，或者三个月后的你自己，只想知道怎么跑起来、目录怎么长、坑在哪；
- c. 潜在用户——在决定装不装之前，先看这项目能替他干什么。

➡️ 推荐 a。你说的是"我们的 Agent 项目"，听起来是给外面看的那一份；b 的内容可以往后放，或者单独开一个 `CONTRIBUTING`，不必抢首页。

---

❓ **Q2** - **读完开头那几十秒，他应该做了什么**：要一个能验证的效果，不要"了解了项目"这种。

- a. 点开 demo 或示例，直接 `git clone` 跑起来；
- b. 记住一句话——"这东西替我干 X"——然后来问你或者来用；
- c. 相信这项目是活的（有真实输出、有更新、有反馈），愿意继续往下读架构。

➡️ 推荐 b 为主、a 为辅：先让陌生人在心里用他自己的话复述"这项目替谁干了什么"，紧接着给他一条两分钟能跑通的路。

答完这两个，我再把"README"这个名词换成一两个动词（比如"让一个陌生人在三十秒内判断这项目值不值得他多花五分钟"），然后从几个最擅长这件事的领域各借一个具体手法给你挑——比如电影预告片的"先给结果再给过程"、开源工具首页的"可复制的最小可跑片段"、落地页的"一句话定位加反面排除（这项目不做什么）"。每条你保留、改写或砍。
