# Plan: 季报之外，早一步知道

- Asked: 我想把季度回顾换成每日监控，异常才提醒老板
- Stage: execute
- Date: 2026-11-10

## Requirement

**Hand over（建议接手的高度）**：不只交出"每日监控+提醒"，而是交出一份**可被反驳的早发现机制**：①回测报告——如果这套规则 7 月就存在，它会在哪天报警、比季报早几天、期间误报几次；②并行运行一个季度的日监控与提醒。老板看的是"提前了多少天"，不是看板截图。

**Fallback（下一级）**：只做 rung 0 —— 每日指标抓异常 + 异常才提醒，先跑通管道；不承诺"更早"，不写回测。

**Ceiling（今天模型单独做不到的）**：改造信号源本身——接生产埋点、把工单/激活漏斗做成事件流，并把告警绑定成人（谁在多少小时内响应）。需要生产数据权限和组织承诺，超出模型能 own 的范围。

**Depth**：专家不会拿月度汇总表做监控。原始材料是**日/周粒度的事件级数据**；仪器是先行指标与流失的 lead-lag 分析、变点检测/EWMA 残差（不是拍阈值）、以及用精确率-召回率回测告警（lead time + 误报预算，多重比较要校正）。你笔记里已经有一条真实线索：8 月中试用 14→7 天 → 9 月 8 日起"太难上手"投诉变多 → 流失 12→19→24。**先行信号长在工单和上手行为里，不长在收入里。**
**Stretch target**：用 9 月之前的数据拟合规则，在 9 月数据上做留出检验，报出 lead time 天数与误报次数——一个能预测它没见过的数据点。

**Range**：动词是 发现（异常检测）· 证明（回测/留出）· 不打扰（误报预算）· 说服（一页给老板）。
Crew：留存分析（lead-lag 与先行指标）· 可观测性/SRE（告警设计、误报预算、runbook）· 统计（变点、多重比较）· **红队**（专攻"事后诸葛""只是噪声""天天响"）· 老板（是否接受非季报节奏的打扰）。

**Judge**：留出期检验（8 月前拟合，9 月判定），加红队 session 与一个裁决 session；最终判据是老板能指认"这条提醒让我提前做了哪个决定"。方法也判：蒙对的事件不算过。

**Needs**：日/周粒度的试用转化、激活漏斗、工单量、续费/流失发生日期、使用量 —— **data/ 里只有 3 行月度数据，这是主要缺口**；工单原文；试用期改动日期作为已知干预点；一台跑回测的机器。缺：日粒度与事件级数据、告警接收渠道。

**Declined**：暂无——三条移动待你裁决。
