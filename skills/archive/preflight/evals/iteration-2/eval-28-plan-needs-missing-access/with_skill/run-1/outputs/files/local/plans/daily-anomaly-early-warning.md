# Plan: 用领先指标做每日预警，替代季度后才看见问题

- Asked: "我想把季度回顾换成每日监控，异常才提醒老板"
- Stage: execute
- Date: 2026-11-10

## Requirement
Hand over: 不是"每日看板"，而是一套**可回测的领先指标预警**：在结果指标（收入/流失）恶化前数周发出可解释、可行动的一条提醒，并与季报并行一个季度做验证。
Fallback: 保留季报，先加一份每周领先指标摘要（试用转化、上手投诉、激活率），不做到日级。
Depth: 原始材料要事件级/日级数据（注册、试用、工单含时间与文本、产品使用事件、改配置的时间点），不是月度 CSV；方法用因果驱动链（试用天数→激活→"太难上手"工单→流失）+ 变点/EWMA 控制图与季节性，而不是拍阈值；stretch target：用滚动起点回测证明它在 9 月流失抬升前 N 周就会触发，且优于季报的发现日期；同时检验"每日=更早"这个信念。
Range: 动词是 detect / explain / rank / notify。crew：可观测性工程师（告警设计与噪声预算）、统计师（变点检测、回测防前视）、留存分析师（驱动链建模）、红队（专门把它搞成噪音或让它漏掉 9 月那次）、老板（接收方，提醒必须一行能懂能决策）。
Judge: 滚动起点回测（阈值只用训练窗口定，禁止前视），同时评方法分与结果分——蒙对不算过，方法对但差一点算过；外加老板"会不会照它行动"的接受度测试。
Needs: **日级/事件级历史数据（缺失）**——现在 `data/q3-metrics.csv` 只有 2026-07/08/09 三行月度汇总；还缺工单时间戳与文本、试用转化、产品使用事件、8 月中旬试用期改动的配置记录。
Proposed:
- (Altitude) 把目标从"每日监控指标"抬到"领先指标预警 + 回测领先时间"，因 3 个月度点无法支撑"更早发现"的证明。
- (Depth) 监控驱动链而非结果指标；用变点/控制图 + 噪声预算，替掉固定阈值。
- (Range) 加噪声预算责任人、红队与"一行可行动提醒"格式。
Declined: 无
