# Plan: 7 天新用户激活邮件序列

- Asked: 重写 onboarding 邮件序列
- Stage: execute
- Date: 2026-11-10

## Requirement
Hand over: 7 天激活旅程的设计（邮件 + 站内触点），仍守 ≤3 封邮件的墙
Fallback: 按原话，只给 3 封邮件的大纲
Depth: 先定"激活事件"、再选"能预测激活的首日动作"，用它反推每封信只推一个动作；一封一封当假设做，配一个 holdout。素材的实测面是产品事件漏斗（按注册 cohort 切），不是文案。Stretch: 先用既有数据说明"哪个首日动作最能预测第 7 天留存"，再让邮件只打那个动作——这是在检验"杠杆在文案"这个信念
Range: 让新注册者完成首个价值动作（定向 orient / 去阻 remove blockers / 证明价值 prove / 提醒 remind）。Crew：生命周期营销（序列逻辑与触发）、产品分析（激活定义与漏斗）、UX writer（每封一个动作），红队 = 送达率/垃圾邮件规则 + 一个从不读 onboarding 邮件的挑剔买家
Judge: 你本人判大纲（便宜、当场）；最终成绩由"发出后 vs holdout 的 7 天激活率"判，它同时判方法——蒙对但方法错不算过
Needs: 缺——现有序列正文（welcome.md 只有一句）、激活事件定义、注册→激活漏斗数据、首个价值动作、名单规模与是否有 holdout 能力
Proposed: ① 抬到"7 天激活旅程"而非 3 封邮件 ② 先定激活事件与预测动作再写文案，加 holdout ③ 大纲旁边附一页测量说明（指标、口径、对照）
