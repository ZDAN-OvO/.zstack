# Plan: 下季 USP 走易用还是便宜

- Asked: 写一份我们 SaaS 的竞品分析报告
- Stage: 决定（决定规则尚未给出，见 Open）
- Date: 2025-11-10

## Requirement

- Hand over: 定位备忘录 —— 结论前置的一句话主张（走易用 或 走便宜）、3 条可验证的支撑证据、以及"另一种选择在什么条件下更优"的翻盘条款。
- Fallback: 两轴空白地图 —— 竞品在"易用度 × 单位价格"上的落点，加一段"要站住易用这个位置，我们必须交付什么"。不直接下结论。
- Depth: 原始材料是竞品自己的免费试用与定价页，不是功能对比表。专家动作：亲自注册 3–5 家竞品，秒表测"注册到第一个核心动作成功"的时长与步数，截图归档；把标价按真实用量折算成每席位有效价（含年付折扣、超量费）。工具：先定权重再打分的评分表、时序测量协议、评论语料编码（G2/Capterra 评论按"贵"与"难用"两类抱怨计数，算各主题的声量占比）。
- Stretch: 用你自己的流失原因/输单原因编码，检验"价格抱怨占比 vs 摩擦抱怨占比"能否预测哪类客户流失 —— 结论要能预测它没见过的数据，而不只是描述市场。
- Range: 报告要让人能 (a) 看见空白位、(b) 看见两个方向各自的代价、(c) 拿去说服团队。crew：定价/包装分析师（价值指标、每席位价）、PLG/UX 研究者（首值时间测量）、评论语料分析师（抱怨声量）、你的销售/支持数据所有者、红队（论证相反方向并指出证据薄弱处）、裁决者。
- Judge: 双层。事实层 —— 新开一个会话，把报告里每个价格与首值时长回查原始页面/截图，查不到即判失败；方法层 —— 红队会话专攻反对方向，再由一个裁决会话裁定。结论本身由你判，因为决定权在你。
- Needs: 竞品名单（3–5 家）、你方基线（现价、首值时长、流失与输单原因）、支持工单/流失问卷/输单记录的访问权、能注册试用（需信用卡？）、公开定价页、评论语料。**工作区当前为空，除公开页面外全部缺失。**
- Declined: 前置大纲 —— 用户要"直接给完整报告"，不设检查点（代价：方向错则整份作废）。
