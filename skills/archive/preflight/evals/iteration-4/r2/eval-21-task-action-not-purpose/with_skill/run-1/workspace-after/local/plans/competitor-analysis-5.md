# Plan: 五家竞品的功能、定价与优缺点

- Asked: 「帮我分析 5 家竞品的功能、定价和优缺点」
- Stage: think（先把意图问实，填满即转 execute）
- Date: 2026-11-10

## Requirement

Hand over: 决策档 —— 下一季度的产品/定价取舍：差异定位图 + 一个推荐 + 反方论证 + 改判触发条件
Fallback: 现状档 —— 五家的能力矩阵、定价结构、优缺点对照（只给事实与差异，不给建议）
Depth: 拿原始材料，不读营销页——定价页的 Wayback 快照（看 SKU 与计费单位怎么演化）、G2/知乎/应用商店的真实吐槽、赢单输单记录；把「价格数字」换成「计费单位与毛利结构」。拉伸目标：用这些材料重建每家过去 12 个月的功能/定价变更时间线，让未参与的人仅凭时间线预测对手下一步动作，命中 ≥2/3。
Range: 不是「一份报告」，而是让人在不确定中取舍、让销售在客户面前说清差别、让下一次调价不再重蹈上次。crew：产品分析师（能力边界）、定价分析师（SKU / 计量单位）、买方研究员（采购路径、赢单输单）、记者（一手来源核对）；红队：做空者 + 对手的销售（逐条攻击结论）。
Range 附带建议: 范围收窄为 3 家重叠对手做深 + 2 家只做价格与定位快照（五家平铺会得到五份雷同结论，判断不了任何取舍）
Judge: 每个数字必须挂一手来源链接，缺源即删；再由攻击会话与裁决会话过一轮。你若能自己判断好坏，你的判定就够。
Needs: 自家产品与客群（缺，阻断项）；五家名单（缺，由你给，不由模型猜）；定价页历史与评论数据（可采）；赢单输单材料（缺）
Declined: —

## Task

Purpose: 待答 —— 这份输出之后要拍哪个决定？（例：主打「更易用」还是「更便宜」、「要不要跟用量计费」）
Context: 待答 —— 自家产品、客群规模、价格带、上一轮调价的后果
Materials: 待答 —— 五家的一手站点与文档、定价页历史、你手上的评论/输单记录；二手评测文章一律不用；查不到就留空，不许编
Boundaries: 待答 —— 哪些输出你会说「不是我要的」？（例：编造的 ARR/用户量、只堆形容词不给取舍、动自家定价区间）
Done: 待答 —— 停下来的标志与形状：先给一份框架（差异在哪、空位在哪、推荐与理由），你点头后再出全文；Markdown，每节 3–4 条
