# Plan：季度回顾 → 每日异常监控（只提醒异常）

状态：草案 v1 · 待确认
目标一句话：把「季报后知后觉」换成「问题早发现、异常才打扰老板」。

---

## 0. 目标与完成定义

**目标**：在问题造成实质损失前发现它（提前量 = 从「季报发现」到「异常发现」的天数差）。

**完成（验收）两条，缺一不可：**

1. **历史可证**：用历史数据回放，同一批已知问题（见 §4 金标准集）的发现时间**早于**当季 QBR 至少 30 天，且告警条数在预算内（§3）。
2. **并行一季**：与季报**并行**跑满一个季度，两个系统结论独立记录；季末对比表见 §6。

> 注意：完成 ≠ 上线告警。**并行期结束前，每日监控只写日志、不对外发消息**（见 §5 阶段 3）。

## 2. 阶段 0：数据可行性（1 周，硬门槛）

**要拿到的最小事件级数据**（缺任何一项都要在周报里标红，不允许用月度数据"凑"出日曲线）：

- 试用开始 / 转付费（含日期、试用时长字段）→ 接住 8/15 政策变更
- 激活里程碑（首日关键动作完成、首次成功事件）+ 上手耗时
- 退订 / 流失（退订日期、原因码）→ 流失日粒度
- 客服工单（创建时间、标签「难上手」、客户分层）
- 账单 / MRR 变动（客户级，含降级与折扣）

**通过标准**：能对 2026-07-01 ~ 2026-09-30 每一天还原出至少这 4 条序列：试用转付率、激活率、流失（客户数与 MRR）、难上手工单占比。
**不通过则**：不做 daily，退化为「周度 + 领先指标」，并把「补齐事件埋点」作为独立项目上报（这本身就是要告诉老板的第一个坏消息）。

## 3. 边界：「不发垃圾提醒」写成硬规则

告警是稀缺资源，按预算发放：

| 规则 | 值 |
|---|---|
| 告警预算 | ≤ 2 条/月，≤ 1 条/周（超出即视为规则过松，回炉调参） |
| 触发条件 | 偏离基线 + 持续性（连续 N 天或 3 点中 2 点越界），**不抓单点波动** |
| 去重/冷却 | 同一指标同一方向 14 天冷却；同源指标合并为 1 条 |
| 分级 | P1 = 立即（收入/流失类越界且持续）；P2 = 当日汇总进日报；P3 = 只进日志 |
| 每条告警必须包含 | 发生了什么 · 证据（图/数字）· 影响估算 · **建议动作 + 责任人** · 免责（"这是信号不是结论"） |
| 不应期 | 已知变更（如定价/试用调整）前后 7 天用「观察模式」，只记不发 |

指标选择原则：**优先领先指标**（试用转付、激活、工单标签、NPS 分项），收入只作确认指标——收入是结果，等它动了已经晚了。

## 4. 阶段 1-2：基线与回测（2-3 周）

**金标准集**（history 里已知的问题，用来判卷）：Q3 的流失翻倍与 NPS 下滑。

**回测方法**：按日滚动，只用「当天及以前」的数据算基线（同比/环比/趋势残差 + 稳健阈值，如中位数 ± k·MAD），输出每日是否告警。
**对比口径**：
- 候选方案首次告警日
- 基线方案（季报）= Q3 结束出报表日 / QBR 日
- 领先天数 = 后者 − 前者

**判卷标准**：
- 领先 ≥ 30 天 → 通过
- 命中率（金标准事件被抓到）≥ 1/1 起，且全期告警 ≤ 6 条（3 个月）
- 误报：人工复核每条告警，标记「真/假/无法判定」；假阳率 > 30% → 不通过
- 用 8/15 政策变更做**事件对齐检查**：告警必须晚于变更、且能追溯到「上手困难」链路，否则是巧合，不算命中

**已知风险**：3 个月数据拟合出来的阈值极易过拟合（尤其 NPS 只有 3 个点）。缓解：参数用先验 + 粗网格，只允许 2 个自由参数；结论标注「样本极小，置信度低」。

**产出**：`backtest/` 下的回放报告 + 一页图（首次告警日 vs 季报日 vs 真实恶化起点）。

## 5. 阶段 3：并行跑一个季度

- 季度 Q4（或下一个完整季），**季报照旧不动**（老板/VP 路径零风险）
- 每日监控：**只写内部日志 + 每周一页摘要**，不直接推老板
