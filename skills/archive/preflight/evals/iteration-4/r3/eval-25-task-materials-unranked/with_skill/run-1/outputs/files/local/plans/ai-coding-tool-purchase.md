# Plan: 下季 AI 编程工具选型与采购

- Asked: 「帮我调研一下国内 AI 编程工具的定价」→「要决定我们团队下季买哪家。资料你随便上网找就行。」
- Stage: 你的目的是 Execute(Decide) 阶段（下季买哪家），但你下的单是 Explore 阶段的活（一张价格表）。中间那块「决策口径」还没定，所以本计划把交付推到「一个可签字的数字」，而不是价格清单。
- Date: 2026-11-10

## Requirement
Hand over: 下季采购决策 memo —— 一家主选 + 备案，12 个月总成本（同口径），席位与用量假设，第二年涨价的触发点，加两条可执行的议价/试用条件。
Fallback: 2–3 家备选 memo（总成本模型 + 各自为什么不选），不碰谈判与上线。
Depth: 原始材料 = 各家官网定价/企业版页（存原页 + 抓取日期）+ 合同/SLA 条款 + 团队上季真实用量日志。专家不会比标价：会做 12 个月 TCO，把年付折扣、席位阶梯、超限单价（token/credit/请求数）折到同一口径，再对「人均日请求量 × 席位数」做敏感性扫描。Stretch: 用团队真实用量日志，在同一份用量下算出每家各自多少钱 —— 若日志缺失，这是最大的方法缺口，不是可以糊过去的细节。
Range: 动词 = 让老板和财务在一个数字上签字，并预判第二年哪家涨价咬人。crew：成本会计（TCO、阶梯、超限）、采购/商务（拆可谈判条款：席位、超限单价、年付、试用转正）、竞品销售（对方会怎么出价）、红队（扮演 CFO 问「为什么不是继续用现在这套」）。
Judge: 每个价格必须回溯到原始定价页 + 抓取日期；模型用脚本把 TCO 重算一遍，与正文数字差 >1% 判失败；再由一个红队 session 专挑口径错误、一个 session 裁定哪些质疑成立。评方法（口径统一、超限建模、来源可查），不评结论顺不顺耳。
Needs: 需联网抓官网（已确认可用）。缺：席位数与角色构成、现用工具/已签合同到期日、预算上限、内网与合规（私有化部署、等保、数据出境）要求、能否开增值税专票、上季用量日志。
Declined: 暂无。

## Task
Purpose: 决定团队下季买哪家。待补：拿什么换什么（省钱 vs 能力/体验 vs 合规）、谁签字、替代方案是什么（继续用现有的？只续一部分席位？）。
Context: 待补 —— 人数与角色、现有工具与合同、预算上限、部署与合规要求、付款与发票方式。
Materials: 你说「随便上网找」= 未排序、无边界，这正是编造价格的入口。建议排序：一手 = 官方定价页/企业版页/合同条款（附抓取日期）；二手 = 只作线索，不取数；禁止 = 测评号与聚合站的「价格」、促销首月价当常态价、截图无日期。找不到 → 留空，不许估。待你确认或改。
Boundaries: 待你给 walls。我提议四条：不得出现无出处或无日期的价格；不得把促销价/首月体验价当常规价；不得推荐开不了票或过不了合规的方案（个人订阅拼车）；不得只给形容词式对比，每项比较必须带权衡与代价。
Done: 先一屏框架（比较维度 + 候选短名单 + 每家计费结构），你点头后再写全文；成品 = 一页决策 memo + 附录（价格来源链接与抓取日期、TCO 模型）。

## Open
- 决策口径未定：预算优先，还是能力/合规优先？这决定推荐谁。
- 席位数、现用工具、预算上限、合规与发票要求 —— 五项空缺。
- 用量日志是否存在：没有它，TCO 只能建立在假设上，结论会退化成「标价比较」。
- 候选范围未定：是否含海外工具的企业版采购，还是只在国内厂商里选。

Ready: no —— 五问只答了两问（Purpose 有、Materials 未排序），Context / Boundaries / Done 空白，Requirement 三轴待你裁定。
