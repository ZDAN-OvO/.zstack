先给一个判断：**「AI 编程」这个题材本身不缺文章，缺的是「你不同意别人的那一句话」**。选题不是选领域，是选一个可以被反驳的主张。比如：

| 主张 | 需要的素材 |
|---|---|
| 「AI 让写代码变快了，让改代码变慢了」 | 你自己项目里 review / debug 的时间账 |
| 「真正的瓶颈从『写得出来』转移到了『说得清楚』」 | 几个 prompt 前后对比的真实案例 |
| 「AI 编程工具的差异不在模型，在上下文供给」 | 同一任务换不同工具/工作流的对照实验 |
| 「它没让新手变强，让强的人更强了」 | 团队里不同水平的人用同一工具的效果差异 |
| 「我删掉了 60% 的 AI 生成代码，但那 40% 值回票价」 | 真实的接受率数据 |

我个人会推荐第二条或第五条——因为它们有**独家素材**，别人抄不走，而你手上大概率就有。

所以想问你三件事，答案会直接决定文章形态：

1. **你自己怎么用的？**（Claude Code / Cursor / Copilot / 手搓脚本？用了多久？每天大概几小时？）
2. **有没有一个具体的「翻车现场」或「真香瞬间」？** 越具体越好，比如某次它连续三次改错同一个 bug，或者一次就猜中了你的意图。
3. **写给谁看？** 同行工程师、团队里的管理者、还是完全不懂技术的读者？

如果你现在什么都还没想清楚，最省力的起手式是：**先写 500 字记录上周你和 AI 协作的一件具体的事**，写完再看它到底在说什么——观点往往是从细节里长出来的，不是先有观点再找例子。
