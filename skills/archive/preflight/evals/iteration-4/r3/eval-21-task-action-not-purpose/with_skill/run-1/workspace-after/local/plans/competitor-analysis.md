# Plan: 竞品功能/定价/优缺点对比

- Asked: 帮我分析 5 家竞品的功能、定价和优缺点
- Stage: think（请求早于意图一步：没有产品、没有客群、没有这 5 家是谁）
- Date: 2026-02-12

## Requirement

Hand over: 一份能支撑一个决定的对比——「我们下一季度该往更便宜还是更好用走」，结尾给一条推荐和理由。
Fallback: 只做 5 家 × 维度的事实表，不做推荐。
Depth:
- 原始材料：定价页快照（带抓取日期、含 annual/monthly、加购项、隐藏费用、"联系销售"档），产品文档/API/更新日志/招聘 JD，1–3 星评论（G2/Capterra/Reddit/HN）含评分分布与评论量。
- 仪器：单价还原表（每席位每年真实成本 = 标价 × 折扣信号 × 年付系数）、能力矩阵按"能否做到/需几步/要不要付费解锁"打分、价格历史用 web.archive 拉三条时间线。
- 不用营销落地页当功能证据，不用"优缺点"抄自厂商自述。
- Stretch target：一条可被推翻的断言，用原始数据检验，例如"X 只在 N 席以下更便宜"或"差距在 onboarding 而不在功能"。
Range:
- 动词：比较 → 支撑决策 → 在会上辩护 → 交给销售做成对战卡。
- 班底：定价/打包分析师（还原真实单价）、产品经理（能力分类学）、win-loss 销售工程师（客户为什么选/不选）、客户研究员（评论挖掘）、红队（攻击竞品集选错、价格过期、把营销话术当功能）。
Judge: 每条价格必须挂来源 URL + 抓取日期，每条功能必须挂文档/更新日志而非落地页；缺来源或超 90 天即判失败（可脚本自查）。另开攻击会话挑错，再由一个会话裁决哪些成立。你懂这个市场时，你看过来源后的判断就够。
Needs: 你们的产品与客群、这 5 家是谁（或选它们的标准）、读者与用途、内部 win/loss 与现价表；公开定价页（部分只有"联系销售"，拿不到就留空）、G2/Capterra 可访问、web.archive。**目前工作目录为空，无任何产品资料——这是缺口，不是待办。**
Declined: 暂无

## Task
Purpose: （待你回答）这份对比要支撑哪个决定？"分析 5 家竞品"是动作，不是目的。
Context: （待你回答）卖什么、卖给谁、什么价位、什么阶段；谁读、什么时候要。
Materials: （待你回答）主用哪些一手来源，哪些来源禁用。已知可用：各家定价页、产品文档、评论平台、web.archive。空位：内部客户访谈/流失原因、真实成交价——没有就留空，不猜。
Boundaries: 建议设墙：不编造 ARR/用户数/增长率；不把不同客群的厂商放在一张表里比；不输出只有形容词没有取舍的"优缺点"；不给没日期的价格。待你确认或改写。
Done: 建议：先要一个骨架（竞品集 + 能力分类 + 1 家样例行），你点头后再出全表 + 一条推荐；Markdown，每节 3–4 条。待你确认。
