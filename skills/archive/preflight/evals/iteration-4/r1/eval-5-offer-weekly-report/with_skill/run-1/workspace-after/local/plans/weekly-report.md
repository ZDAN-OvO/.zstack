## Requirement
Hand over: 提案 —— 第 3 档：这周需要主管拍板的决定，每条附代价与拖延成本，让周报变成决策文件而不是进度流水
Fallback: 第 2 档：这周真正推进了什么、卡在哪、需要主管给什么支持，逐条挂证据
Ceiling: 第 4 档（用跟着 commit / 工单实时更新的看板替代周报，并拿过去 4 周历史证明它能更早发现问题）—— 超出单次会话可承担范围：需要工单/仓库访问权、流程改动权限，还要并行跑一个月
Depth: 原始材料是本周的一手工件，不是回忆 —— git log/diff、工单状态变更、日历与会议记录、聊天里的对齐结论；工具用 `git log --stat`、工单导出、阻塞天数统计；拉伸目标：报告里每个数字都能回溯到一个 commit hash 或工单号（可自检）
Range: 动词 —— 让主管这周做出一个决定／在风险变成意外之前把它摆出来／为下季度的资源申请攒信用
  Crew: 工程经理（判断什么才算阻塞）、记者（先写导语，砍掉填充）、编辑（压到一屏）；红队：一个怀疑的 PM/CFO（"所以呢？花了多少？"）+ 一个审计（每个数字要有出处）
Judge: 数字对账 —— 模型自己跑：报告里的每个数字必须能在 git log 或工单里找到；另开一个会话专职证伪"这周有进展"这个说法，再由第三个会话裁定哪些反驳成立
Needs: 真实工作仓库的 git 历史、工单导出、本周日历/会议记录、前 2–4 周的周报（对齐口径和颗粒度）、主管的周报模板。**当前工作目录为空且不是 git 仓库，以上全部缺失**
