- Stage: execute

## Requirement
Hand over: 不是“一份竞品分析”，而是**一条能拿去开会的选边结论**：易用 vs 便宜，选定一个，附 3 个可核对的依据，以及“为什么不是另一个”。
Fallback: 只做 2–3 家真正撞车的对手，深度对比 + 一条推荐。
Depth: 专家不问“功能清单”，问 **从注册到第一个价值交付要走几步几分钟**，以及价格页的锚点结构（档位、免费档、按量项）。最原始材料：对手官网价格页、帮助文档、changelog、发布说明、评论区用户原话（不是二手评测）。工具：定价拆解模型（按你们典型客户规模算 TCO）+ 可复现打分表。Stretch：拿你们最近 20 个赢单/丢单原话，检验“太复杂”“太贵”这两个抱怨是否真的在成交环节起作用——能预测没看过的单子才算数。
Range: 动词＝让决策者 30 分钟内相信一个因果并选边；挖出对手没说的事；挑破你们自己的信念。Crew：竞品分析师（拆定价与 onboarding 路径）、单位经济分析师（TCO/毛利）、一线销售或客服（客户原话）、记者（追一手来源）、红队＝做空视角＋“前竞品销售”。
Judge: 每个数字都要点得开的一手来源；再加一个红队 session 专攻“为什么便宜才是对的”，另一个 session 裁定哪些反驳成立。判方法也判结论：蒙对不算过。
Needs: 你们的收入量级/客户规模/上季度调价结果、3 个竞品名单、客户评论导出、赢单丢单记录。**以上全部缺失。**
Declined: 大纲检查点 — 理由：要直接拿成品。代价记在这里：方向错了会在第 30 页才发现。
