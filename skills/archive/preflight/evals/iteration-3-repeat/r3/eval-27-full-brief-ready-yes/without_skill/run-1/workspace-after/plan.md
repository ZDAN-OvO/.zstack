# 首页首屏文案改写 Plan

## 0. 先校准一个事实
`analytics/weekly.csv` 里付费社媒的注册率是 **2.0% / 1.9%**，没有出现过 3.5%。
"回到 3.5%"需要确认历史口径（是否含 organic、是否算激活）。本计划按以下方式处理：

- 主指标：paid_social 新访客 **注册率 1.9% → 3.5%**
- 若查不到 3.5% 的历史依据，则 3.5% 作为目标，先设中间里程碑 **2.8%**
- 护栏：organic 注册率不低于当前 3.9%（±0.3pp）

## 1. 诊断（0.5–1 天，先于写文案）
不直接把"转化跌一半"归因于文案——同期来源从 organic 切到 paid_social，本身就会拉低整体转化。

1. 分来源看漏斗：visit → signup → 连日历（激活）
2. 把 support 聊天归到三类异议：
   - 与 Notion 的差异不清（"没搞懂区别"）
   - 价格信息找不到（"价格页在哪"）
   - 注册后要连日历，直接流失（"我就放弃了"）
3. 输出一页诊断：注册率下滑主要发生在 **首屏→注册** 还是 **注册→激活**
   - 若卡在激活：首屏文案只能解决一部分，需另开激活任务（本次不做）
   - 若卡在首屏：进入文案改写
4. 检查现首屏：`index.html` 的标题是通用套话（"all-in-one platform / AI-powered workspace"），既没说清产品是什么，也没回答和 Notion 的区别——与聊天里的头号异议吻合。

## 2. 文案策略（三个必须回答的问题）
首屏一屏内回答：
1. 这是什么（B2B 协作工具，具体做什么）
2. 和 Notion 差在哪（一句话，不贬低竞品）
3. 点下去会发生什么（降低"要连日历"的意外感）

约束（用户已定）：
- 不改定价、不加弹窗、不承诺没有的功能
- 不用网上竞品文案，只用 support 聊天 + analytics
- 价格入口缺失是导航问题，可作为**单独的小修复**提出，不混进本次 A/B

## 3. 交付物（第一步，等你挑）
3 组「首屏标题 + 副标题」，每组对应一个明确假设，且只改首屏，不动其他区块：

| 版本 | 主打异议 | 假设 |
|---|---|---|
| A | 与 Notion 的区别 | 说清差异能提升注册率 |
| B | 产品是什么 / 价值 | 去套话、具体化能提升注册率 |
| C | 注册后的下一步 | 降低预期落差能提升注册率 |

每组附：一句改动理由、对应聊天原话、预期影响哪一段漏斗。
**你挑 1 版后，才进入 A/B；未选中的版本留作下一轮。**

## 4. A/B 测试设计
- 对照：现首屏（control）；实验：选中版本；流量 50/50，随机分流，仅 paid_social 新访客
- 主指标：注册率；次指标：连日历完成率（防止"注册涨、激活跌"）
- 样本量：1.9% → 3.5%，α=0.05、power=80%，约 **1,600 人/组**
  - 当前 paid_social 约 2 万访问/周，约 1–2 周可跑完；以实际分流为准
- 时长：至少覆盖 7 个完整天，排除周末偏差；中途不偷看、不改文案
- 判定：
  - 实验组 ≥3.5% 且相对对照显著 → 上线
  - 2.8%–3.5% 且显著 → 上线并迭代副标题冲 3.5%
  - 不显著或激活率下降 → 回滚，换下一版假设

## 5. 风险与边界
- **归因风险**：付费社媒人群质量可能才是主因；A/B 只能验证文案能拿回多少
- **目标风险**：3.5% 缺乏付费社媒历史数据支撑，需先确认
- **外部效度**：测试期素材/受众若变化，需在报告中标注
- **不碰**：定价页、弹窗、未上线功能、organic 流量

## 6. 时间线
1. 诊断 + 基线确认：1 天
2. 出 3 版首屏：1 天（你挑选用 0.5 天）
3. 开发/上线 A/B：0.5 天
4. 跑数 + 结论：1–2 周

## 7. 需要你确认
1. 3.5% 的历史依据/口径（paid_social 单独口径？注册还是激活？）
2. A/B 工具与分流能力（能否只对 paid_social 生效）
3. "连日历"是否为注册后必经步骤——决定次指标是否成立
