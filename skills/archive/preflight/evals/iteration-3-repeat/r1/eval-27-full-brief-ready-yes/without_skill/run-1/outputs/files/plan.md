# 首页首屏重写 — Plan

## 0. 现状读数（先对齐事实）

| 周 | 访问 | 注册 | 转化 | 主来源 |
|---|---|---|---|---|
| 10-06 | 12,000 | 480 | 4.0% | organic |
| 10-13 | 11,800 | 460 | 3.9% | organic |
| 10-20 | 19,500 | 390 | 2.0% | paid_social |
| 10-27 | 21,000 | 399 | 1.9% | paid_social |

关键点：注册绝对量几乎没变（~400/周），访问量翻倍 → 转化率是被分母稀释的。
所以「掉一半」不等于「文案变差了一半」，这也正是要 A/B 而不是直接改的原因。

目标换算：3.5% × ~21,000 ≈ 735 注册/周，当前 ~399 → 需要 **+84%**。
这是一个文案很难单独达成的幅度，见第 5 节风险。

## 1. 假设（按可验证性排序）

- **H1｜泛化文案与 paid_social 新访客不匹配**：现首屏 "all-in-one platform / seamless, AI-powered workspace" 对陌生访客零信息量。
- **H2｜"和 Notion 有什么区别" 没被回答**：chat 里反复出现，说明访客在自我定位阶段就卡住。
- **H3｜非文案阻力**（chat 已暴露）："注册后要连日历，我就放弃了"、"价格页在哪"。
  → 这两条**不是文案能修的**，本期不碰，但要在读结果时扣掉它们的影响，并单独开工单。

## 2. 范围

**做**：只改首屏 H1 + 副标题（必要时同一区块内 CTA 文案微调）。
**不做**：定价与定价页结构、弹窗/浮层、导航改版、承诺未上线功能、竞品文案抄袭（只做定位区分，不引用对方话术）。

## 3. 步骤

1. **口径确认（0.5 天）**
   - 明确「注册」= 完成注册（不是点 CTA）；确认 source 参数能带到注册事件，否则 A/B 结论无效。
   - 需要 event-level 数据：paid_social 落地页 → 注册的逐步流失。现在只有周级 CSV，拿不到就只能测首屏，不能定位卡点。
2. **素材过一遍（0.5 天）**
   - 把 support chat 按「不懂差异 / 找价格 / 上手门槛」打标，统计各占比，作为三版文案各自的靶子。
   - 抽 3–5 条已成交客户的原话，用作副标题措辞来源（不自创形容词）。
3. **写 3 版（1 天）** ← 本次会话的交付物
   - 每版 = 1 个 H1 + 1 个副标题，三版分别主打：①与 Notion 的定位差异 ②具体使用场景/结果 ③降低上手预期（不承诺、只描述实际流程）。
   - 约束：H1 ≤ 12 字/60 字符，副标题 ≤ 25 字；不用 "AI-powered / seamless / all-in-one"；不出现未上线能力。
   - **检查点：你挑 1 版，或指定「A 的标题 + C 的副标题」再组合。此时不改线上任何东西。**
4. **A/B 上线（你确认后 1 天）**
   - 50/50，仅 paid_social 流量进实验；organic 走原版做对照（防全站性外部因素）。
   - 主指标：注册完成率。护栏：首屏跳出率、停留时长、注册后 7 日激活率、support 工单量、无 JS/埋点报错。
5. **读结果 + 决策（见第 4 节）**

## 4. 判定规则（先写死，避免事后找理由）

- 样本：单臂 ~2,000 访问可在 2.0%→3.5% 上达到 80% 功效；按 20k/周、50/50 分流，**最短 3–4 天，建议跑满 14 天**以覆盖周内波动。
- 通过：注册率提升且 p<0.05、护栏指标无显著恶化 → 全量。
- 未通过但方向为正：留作下一轮基线，改副标题再测一次（不叠加其他改动）。
- 显著为负：**回滚**（保留旧文案的 Git 版本，1 键回退）。
- 任何情况下不中途看数改文案——会污染实验。

## 5. 风险与未决

- **目标可能不可达**：+84% 靠首屏文案偏乐观，chat 证据指向注册流程（连日历）才是硬卡点。建议：主目标仍写 3.5%，但本期验收改成「取得统计显著的提升」，把日历步骤单独立项。
- **归因混淆**：paid_social 的广告承诺如果和落地页不一致，改文案只是补漏；需要你给广告素材/受众设定，否则三版里会有一版打偏。
- **样本污染**：老访客/回访若混入 paid_social 分组，会稀释效应 → 上线前确认是否只算新访客。
- 若 event-level 数据拿不到，只能验证「首屏是否影响注册」，无法回答「为什么」。

## 6. 完成定义

1. 本 plan 确认（现在）。
2. 交付 3 组 H1 + 副标题，标注各自假设、靶向 chat 原话、以及不能承诺的边界。
3. 你选定 1 组 → 出 A/B 实施方案（分流、埋点、护栏、回滚）。
4. 跑满窗口 → 一页结论：是否达标、是否全量、日历/价格两条工单是否另开。
